# 心灵传感器升级方案：测量、模型与状态工程

日期：2026-10-30。配套阅读：`psyche-report-2026-10-30.md`、`psyche-upgrade-psychology-notes-2026-10-30.md`、`psyche-upgrade-ml-notes-2026-10-30.md`。本方案基于只读审阅；没有启动 3352、FLM 或 Ollama，也没有修改运行时代码。

## 结论

当前 VAL 契约是比旧 JSON 更合适的轻量基线，但还不能安全写入角色状态。现在最重要的升级不是继续调 prompt 或立刻训练，而是明确它测什么、让非法输出和未知输入可以不更新、重建独立评测集，并明确 Anima 中哪一处拥有“当前情绪状态”的写入权。

需要把三个不同目标分开：

1. **传感器**：从一轮互动中估计新的事件评价（appraisal）及证据是否充分。
2. **状态更新器**：由确定性代码合并新评价、上一状态与真实时间间隔，维护短时 mood。
3. **消费者**：把有来源和时间戳的状态用于检索或回复提示，并能证明它确实改变了产品行为。

模型输出不是心理事实，也不是状态机。`neutral`、`unknown`、`invalid` 和“系统消息等明确无事件输入”要分别表示；不能都折叠成 `VAL=0`。

## 代码审计：当前实际行为

生产脚本在 `D:/castalia/run/Castalia/scripts/psyche_npu.mjs`，而本工作区只包含文档。新增 `/appraise` 端点没有找到 Anima 消费者；它仍是独立传感器。

Anima 有两条 VAD 路径：`autoProcess()` 把用户消息放入队列；`maybeDigest()` 触发 `flushVadQueue()`；批量分类会把逐条消息 VAD 写回记忆，`search.ts` 用它计算情感强度、衰减与检索排序。此外，队列还会分析近期消息的整体轨迹并更新 `smoothedByProject`，但该平滑值只在进程内 Map 中。`getSmoothedVAD()` 与 `formatVADForPrompt()` 在 `src/` 里只有定义/导出，没有找到实际状态读取或 prompt 注入调用；进程重启后平滑值从人格基线初始化。故“新端点未接入”成立，“Anima 情感数据完全空转”不成立；更准确地说，持久化/检索使用逐条消息音调，轨迹平滑状态则尚无消费者。这两者都不等同于“本轮互动如何改变角色状态”。

## 先修测量定义

建议把目标定义为：**从当前对话里可观察到的互动行为，估计它对角色当前目标的事件级评价方向；不是诊断用户情绪，也不是读取角色真实内心。** 把对话原句、角色/目标、前置状态估计和本轮新证据分栏。前置状态是带来源和时间戳的先验，不应覆盖本轮相反证据；本轮输出只描述增量。

`neutral` 表示标注规则下有足够证据认为本轮情绪影响接近零；`unknown` 表示上下文缺失、正负证据冲突、目标不明或讽刺无法判别；`invalid` 表示模型输出不符合契约。明确的空输入或系统元数据可以走 `no_event`，它是流程控制，不是自然语言情绪判断。问句、短句和“没出现情绪词”本身都不能当作 neutral 规则。

标签指南至少应包含：方向、强度档位、被评价的互动行为、证据片段、是否依赖历史、neutral/unknown 的边界、讽刺/反话/道歉/关心/事务性语句示例。对于同一句话在不同历史状态下含义不同的情况，分别标注当前轮 evidence 和整个序列结果。

## 推荐升级顺序

### 1. 封闭并加固运行契约

- 继续把当前 VAL 短契约作为基准候选。解析只接受完整响应 `VAL=-2|-1|0|1|2|?`（或明确版本化的等价格式）；越界、夹杂说明、多个数字、空输出均记 `invalid/abstain`，绝不静默 clamp 成有效类别。
- 在调用边界检查输入类型、文本长度和总体请求体大小；对 warm 与推理设置 AbortSignal 超时。超时、NPU 错误、被拒绝的低内存请求分别计数。
- 每个模型/端点使用单飞加载；推理串行或使用小型有界队列。保持 active inference lease，lease 清零前不允许 idle/RSS unload。队列满时返回明确 `busy`/不更新。
- loaded cache 绑定 model、endpoint 与加载代次；任何失败、卸载、配置变化都让缓存失效。修复 `minFreeMb` 持久化和 `--load`，再测 idle unload 的真实路径。
- `health` 状态检查不要在请求处理线程中执行多次同步 PowerShell/CLI 查询；为健康检查与推理状态建立有时效的监控缓存。

### 2. 重做评测集与计分

- 先从真实对话构造版本化语料，所有同义改写、连续轮次和同一语义场景归到同一组。按会话/用户分组，额外留出较新的时间段；few-shot 示例不得与验证/测试样本重合。
- 由两名标注者独立标注关键样本，记录分歧并裁决。保留完整 3×3 混淆矩阵，另外报告 `unknown/invalid` 数量、覆盖率、覆盖条件下风险、每类 precision/recall、macro-F1 与多数类/简单规则基线。
- 置信区间以会话或语义组为单位做 cluster bootstrap，模型比较用同一批配对样本。报告方向和强度两项，不把 paraphrase 的多次措辞当成独立样本量。
- 把数据按普通/讽刺/否定/道歉/关心/冷淡短答/正负混合/需状态历史分层。分别看跨场景与跨时间表现，而非只给一行总准确率。
- SDT 可以留作辅助分析，但需明确 signal/noise 编码、neutral/abstain 的处理与连续性修正，报告完整分母和区间。`psyche_sdt.mjs` 的 `.filter(r => r.got)` 只排缺失或空预测；当前 `sign` 是字符串，所以 `'0'` 会保留到下一步，再由 `want !== '0' && got !== '0'` 排除。这样各模型的命中率和虚报率基于不同的非中性覆盖子集，不能直接横比；应同时报告 neutral/abstain 覆盖率，并在固定共同子集上补充比较。当前脚本把每个零计数单格替换为 0.5，不是整体 log-linear correction，小样本 `d'` / `c` 应降权解释。脚注把“偏保守”和“爱报冷”并列，语义冲突；负向为 signal 时 `c<0` 是更倾向报负向。无论如何都不能把 `c=-0.51` 直接换算成 `delta×0.6`。

### 3. 用同一标注集比较模型路线

保留 0.8B VAL 为现有成本/隐私基线，再加上多数类、少量高精度跳过规则、一个小型中文 encoder 分类器（如合适的 MiniLM/MacBERT/DistilBERT 变体）和 SetFit。输出只是闭集类别时，判别式头不必生成解释或 JSON，值得测其准确率、延迟和部署内存；通用论文不保证它在本机 NPU 上一定胜出。

如果真实标签数据还少，可先用主模型或 API 辅助预标，再由人工抽样复核和裁决；teacher 不能直接充当 gold。积累足够真实标签后，再评估 SetFit / 小 encoder 微调，或把教师行为蒸馏到本地分类器。部署基准要包含当前硬件、ONNX/量化版本和冷/热调用；不要只按参数量选模型。

主模型自评也只是候选传感器，应做消融以证明对标注目标有增量。API 级联先离线回放，以 invalid、已校准的边界风险或已测过的模型分歧作为路由候选；自报 certainty 和同 prompt 的重复采样一致性都不能直接当概率。

### 4. 再接状态更新和回复提示

- 为状态指定唯一 owner。优先决定新 appraisal 是否扩展 Anima 的现有 VAD 状态，或仅作为另一条事件信号；不要让 `/appraise` 和 `emotion.ts` 各自写一个 mood 真值。
- 用纯函数 `next = transition(previous, appraisal, dt, eventId)` 更新状态。`abstain/invalid/no_event` 不产生新证据；已处理 eventId 不得重复累加；VAD、连续 delta、基线与时间衰减的单位必须在 schema 中写明。
- 持续时间、惯性、滞回阈值从真实重复轨迹中拟合或做敏感性分析。心理学的 affective inertia 支持“个体的情感时间动态有差异”，不提供可直接复制到虚拟角色的半衰期常数。
- 先 shadow 写入状态和指标，不影响生成；再做 A/B 注入。注入文本把“日志观察”“历史状态估计”“当前轮证据”分开，并允许新证据推翻旧状态。评价最终状态轨迹及回复质量，而不只是看模型是否顺从状态提示。
- 对每轮跟踪 queue age、解析成功率、类分布、neutral/unknown/invalid、状态是否更新、消费者是否读取、p50/p95、模型加载/卸载和失败原因。没有消费者读取的状态只算存储成功，不算功能完成。

## 研究依据与边界

心理学文献可支持“核心情感、事件评价、表达、长期人格是不同概念”，并支持从重复时间序列估计情感动态；不能替系统规定正确的虚拟人格值。Russell 的核心情感、Scherer 的评价过程、Fleeson 的特质/状态分布、Kuppens 等人的个体情感动态可见心理补充文档中的 DOI 链接。

格式约束研究（Tam et al.; Ray 的 *The Constraint Tax*）提醒结构合法不代表语义正确，且约束代价依任务和推理负荷而异；本机 VAL 的配对 A/B 才是该任务最直接证据。Xiong 等人的不确定性研究不支持任何单一置信度方法普遍胜出。Conformal abstention 需校准数据与可交换性等前提，按会话和时间漂移的数据不能直接承诺同样的错误上界。

SetFit、DistilBERT 给出少样本和蒸馏 encoder 的候选工程路线，不是当前硬件的质量承诺。GoEmotions 展示人类情绪标注的细粒度与边界问题，但 Reddit 标签不迁移为角色互动 gold。vLLM 与 AMD GitHub issue 是特定后端/设备的社区故障经验，可帮助列压测项，不能解释本机的 ERT 错误根因。

此外，原报告提及的负面偏置、前景理论损失厌恶、峰终规则和情绪分化都不能推出“valence 固定乘 2”或当前某一阈值。原报告里的 `d'` / `c` 在本次没有逐样本数据下无法独立重算；当前值只应当作探针集的描述统计。

## 验收门槛建议

正式接入前至少满足：严格解析，任何非法输出不更新状态；按用户/会话/时间留出的 locked test；各类混淆矩阵和 cluster 区间；neutral 与 abstain 的独立指标；状态更新纯函数可回放且防重复事件；模型故障/并发/卸载路径压测通过；shadow 阶段确认新状态确实被唯一消费者读取。目标准确度、最大 API 比例、成本和延迟门槛应根据标注后的错误代价和机器预算确定，不由当前 20/36 条探针直接设定。
