## 一、现在一次调用到底怎么跑的（自回归逻辑全貌）

```
一轮对话结束（用户一句话 + 她的回复）
  │
  ├─ POST /appraise {user, assistant}          ← 只有这一轮原文。没有历史、没有上一轮状态、没有动作
  │
  ▼ psyche_npu.mjs · appraise()
  │    读盘取配置（--off 实时生效）→ 内存闸 minFreeMb → 冷则 1-token 预热（26s）→ 直接请求
  │
  ▼ prompt = SYS(10 行 rubric) + 12 × (user/assistant 示例) + 本轮
  │    约 1100 token，其中 ~70% 是那 12 个示例
  │
  ▼ POST /v1/chat/completions  {temperature:0, max_tokens:128, response_format:json_object}
  │
  ▼ FLM 在 NPU 上**贪心解码一个 JSON**，token 顺序固定：
  │      goal → valence → control → certainty → tag → why
  │
  ▼ JSON.parse → { appraisal } → 返回 → **到这里断了**
```

四个必须在设计里认下来的性质：

1. **它是无状态函数**，不是状态机。prompt 里没有 t−1 的任何痕迹：同一轮文本，前面聊了 8 轮还是第 1 轮，输入完全相同。状态机该有的 `s_{t+1} = f(s_t, o_t)` 里的 `f` 现在不存在——不是"效果不好"，是代码里没有。
2. **标签是在数字后面续写的**。tag 是模型读完自己刚吐出的 4 个数字后接着生成的；`why` 又在 tag 之后。所以 `why` 是对已输出结论的续写合理化，不可能反过来修正 tag。拿它当"依据"读会骗自己。
3. **这条链路目前是空转的**。`grep -rl "3352\|appraise" D:\castalia\run` 只命中 `castalia.config.json` 与 `psyche_npu.mjs` 自己——没有消费者。和 hotmolts 那个《Silent When It Should Talk》是同一种失败形状：算出来了，但既没进注入也没进 UI。
4. **约束解码只保证结构，不保证范围**。68 条里有 1 条 `valence=3`（契约是 −2..2）。代码必须自己 clamp。

## 二、自回归带来的四个可测偏差（都是本次量出来的）

| 偏差 | 证据 | 对状态机的含义 |
|---|---|---|
| **字段换序就换结论** | 同 10 条输入，只把输出字段顺序改成 tag 先：sign 一致 8/10、tag 一致 7/10 | 判定有 20–30% 是 token 顺序的产物，不是"读懂了" |
| **标签层把中性抹掉** | 全契约：0/68 落在 \|valence\|<0.25；只问 valence 时 2/20 会报 0 | 契约越长越"必须表态"，状态机拿不到"休息"档 |
| **数值量子化** | 0.8B：valence 只有 6 个取值、−0.5 占 54%；control 71% 是 −1；certainty 只有 0.7/0.8/0.9（45/68 是 0.8） | 4 个 dim 合计约 **1 bit** 信息：control 与 certainty 基本是常数 |
| **结论可复现，但不是"算出来的"** | 同一提示词 3 次（含冷加载重跑）：20/20 完全一致；换成旧探针那版（多一条规则、位置不同）：只差 1 条 | 它稳定地重复同一个启发式，而不是稳定地"判断" |

### 合并 68 条逐轮判定的混淆矩阵（行=期望，列=判出）

|        | + | − | 0 | 召回 |
|---|---|---|---|---|
| **+**  | 15 | 8 | 0 | 0.65 |
| **−**  | 3 | 35 | 0 | 0.92 |
| **0**  | 1 | 6 | 0 | **0.00** |

- 方向准确率 **0.735**（Wilson95 0.62–0.83）；「一律判负」基线 0.559 → 真实增益约 **+18pp**。
- 干净留出集 20 条：12/20 = 0.60（Wilson95 **0.39–0.78**），多数类基线 0.50。样本太小，不足以宣称"比一半强很多"。
- 输出分布：判出 0 的次数 **0/68**；判负 49/68。标签 12 类里只用了 9 个，**被敷衍×17 + 被拒绝×13 = 44%**。
- 2B 对照：方向一样 0.75/0.60，但**分布是正的**（+ 36 条、− 29 条、0 ×3），12 类全用上，`+` 召回 0.96。
  → 0.8B 的高分里有相当部分是"永远偏冷"拿到的高 − 召回；2B 花 1.7GB 买的是**校准**，不是准确率。
- **certainty 不能当闸门**：≥0.9 组 75%、0.8 组 71%、<0.8 组 100%，单调性不成立。

## 四、判定：0.8B 当传感器可以，当状态机不可以

**可以的部分**（这是它唯一站得住的用途）：
- 单轮、异步、不进回复路径；0 失败；1.5 s；2.1 GB；同一提示词跨加载完全可复现。
- 只输出"这一轮把她往暖 / 往冷推"，配合确定性代码做动力学。

**不可以的部分**（三条都有数据）：
1. **它没有状态输入**。给它前文，4 组里只有 2 组会改变判定；其它两组纹丝不动。要它携带状态，只能把状态塞进 prompt——那就已经是在外面做状态机了。
2. **它的"中性"是死的**（0/68）。接进去的直接后果：她的心情只会单向变冷，且 44% 的时间显示"被敷衍 / 被拒绝"。这不是参数没调好，是分布塌了。
3. **它的标签不能当状态名**。12 类在 68 条上只覆盖 9 类，两类占 44%，且标签与 valence 有 3/20 自相矛盾（dims 说正向、tag 说被拒绝）。状态名必须由代码派生，不能由模型贴。

**规模不解决问题**：0.8B→2B（+1.7 GB）方向准确率不变（0.60→0.60），只修好分布；2B→4B（+5.5 GB）方向升到 0.80，但 45% 调用直接 500、内存也塞不下。瓶颈在契约，不在参数量。

**该长的形状**（对齐 `psyche-state-machine-survey.md` 的结论，这次有了数字支撑）：
1. 传感器 A：主模型自评 `<psyche_eval>`（0 额外调用）为主；
2. 传感器 B：0.8B 只在自评缺失/冲突时兜底，**只取方向**，`tag` 仅用于解释文案；
3. 状态机：`next = transition(prev, delta, dt)` 纯函数 + 进入/退出双阈值 + 最小停留 + 单一写入闸；离散状态由 PAD/VAD 派生；
4. 兜底：失败/超范围/|valence| 判不出 → 按 0 处理（本次 4B 的教训）；数值 clamp 到契约范围；
5. 中性交给确定性规则（纯信息问句、单字应答、无情绪词）——不要指望 0.8B 判 0。

**顺带一个可换的性价比**：只输出 `{"valence":…}`（去掉 tag/why/三个 dim）→ 延迟 1.55 s → **0.80 s**，
方向 11/20 vs 12/20（差 1 条）。如果只要方向，这是免费的延迟收益；那 1 条差距也说明"标签层不参与方向判断"。
